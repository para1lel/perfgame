# 前端设计

## 设计方向

这个产品的实质是：**一个人盯着数字，判断自己写的代码离硬件极限还有多远**。它需要一个像仪表的东西，而不是像营销页的东西。

LXGW WenKai 是强制约束，这反而给了方向。它是一支带书写笔意的楷体，暖、有呼吸感；而 GPU kernel、PTX、roofline 是冷的、精确的。把两者放在一起，最自然的结果是**一本用好的纸印出来的实验记录本，上面贴着仪表读数**——而不是又一块霓虹黑终端。

于是三条原则：

1. **纸感优先于玻璃感。** 表面上墨，不叠发光、不叠毛玻璃。层级靠色阶与留白，不靠阴影。
2. **唯一的高饱和出现在数据上。** 界面本身几乎无彩；分数、SOL 百分比、roofline 上的点才有颜色。用户扫一眼就知道该看哪里。
3. **结构性线条只编码结构。** 表格的竖线划分列，rail 的刻度划分分数档。没有纯装饰的线、没有编号装饰、没有全大写小标签。

### 被拒绝的方案

- 深色 + 荧光绿（"CUDA 终端"联想）：这是同类产品的默认答案，且和 WenKai 的气质正面冲突。
- 米色纸 + 陶土色强调：当前生成式设计的头号陈词，且会把 WenKai 推成"文艺"。本项目的纸是冷灰绿，不是米黄。
- 卡片网格：每道题的元信息量与"卡片"这个容器不匹配，表格更省地方也更好比。

## 排版

### 字体

| 角色 | 字体 | 说明 |
| --- | --- | --- |
| 正文、标题 | LXGW WenKai | 全站唯一非等宽字体。标题也用她，大字号下楷体的横细竖粗很耐看，不需要第三支字体 |
| 代码、数字 | FiraCode Nerd Font | 连字开启；`zero` 开启（0 带斜线，区分 O）；`tnum` 开启（数字等高，便于对齐分数列） |

CSS：

```css
--font-prose: "LXGW WenKai", "LXGW WenKai Screen", serif;
--font-mono: "FiraCode Nerd Font", "FiraCode NF", ui-monospace, monospace;
```

字体通过 `@font-face` 自托管（`frontend/public/fonts/`），不走第三方 CDN——部署链路不稳，字体加载失败会让整站气质崩塌。子集化：中文按 GB2312 常用字 + 项目用字生成 woff2，拉丁与符号全量。

### 字号与行距

以 17px 为正文基准（WenKai 在 16px 下偏小）。行距比无衬线更松，楷体需要。

| 层级 | 大小 | 行距 | 字重 | 用途 |
| --- | --- | --- | --- | --- |
| 展示 | 2.5rem / 40px | 1.2 | 500 | 题目页标题、总分 |
| 一级 | 1.75rem / 28px | 1.3 | 500 | 页面标题 |
| 二级 | 1.3rem / 21px | 1.4 | 500 | 章节 |
| 三级 | 1.06rem / 17px | 1.5 | 700 | 小节、表头 |
| 正文 | 1.0625rem / 17px | 1.75 | 400 | 题目描述、文档 |
| 小字 | 0.875rem / 14px | 1.6 | 400 | 元信息、辅助说明 |
| 微 | 0.78rem / 12.5px | 1.5 | 400 | 时间戳、单位 |
| 代码 | 0.9rem / 14.4px | 1.7 | 400 | 编辑器、PTX、日志 |

正文行宽上限 **68 字符**；题目描述与文档放宽到 **74**（楷体可以稍长）。从不做两端对齐。

### 数字

分数、耗时、百分比一律 FiraCode + `tnum`。理由：一列分数上下对得齐，扫读效率翻倍。这是对等宽字体的功能性使用，不是装饰。

单位跟在数字后，`--ink-muted`，不换行：`12.43 ms`、`812 GB/s`、`96.4 %`。

**左侧题面**的结构固定为：标题 → 一行元信息 → 下界摘要块 → 题面正文（problem.yaml 的 `description`，Markdown）。

下界摘要块不是正文的一部分，用 `--surface-sunk` 底、无边框、`--font-mono` 数字、左侧一条 2px `--primary` 竖线。三行：计算量、访存量、达标时间。**"你必须在 1.64 ms 内完成才过关"** 是全页最重要的一句，用 `--signal` 显示——这是唯一使用暖色的正文句。

**右侧编辑器**：顶部是语言下拉 + 文件名 + 校验按钮；中间 Monaco；底部一行工具条（产物标签页、格式化、提交）。提交按钮固定在右下，`--primary` 实底。

### 结果面板

提交结果的展示不是弹窗，是**从编辑器下方升起的托盘**，占编辑器高度的 55%。理由：看分数时还要对照代码，弹窗会遮住。

托盘顶部一行：总分（FiraCode 40px）+ 达标率条 + 重测/Profile 按钮。

达标率条是一条水平 rail，标出 70% 刻度线。每个测试点一个小方块落在 rail 上，位置是它的 roofline efficiency。**这就是全站的标志性视觉**，比大数字更能说明"你离极限有多远"。

```
0%        35%        70%            100%         150%
│          │          │               │            │
├──────────┼──────────┼──────●────────┼────────────┤
│          │          ▴ 70% 满分      │            │
```

方块用 `--primary`（通过）/ `--danger`（未通过）/ `--signal`（未测完）。悬停显示测试点名与效率。

下方是折叠列表，每行一个测试点：名称、状态点、耗时、效率倍数、分数。展开显示逐元素合格率、最大误差、余弦相似度、5 次采样柱状图。

## 编辑器

Monaco，配置如下，逐项都有理由：

| 配置 | 值 | 理由 |
| --- | --- | --- |
| `fontFamily` | FiraCode Nerd Font | 连字 `->` `>=` `!=` 更有辨识度 |
| `fontLigatures` | `true` | 同上；`calt` + `zero` 开启 |
| `fontSize` | 14.4 | 与正文 17px 的比例协调 |
| `lineHeight` | 1.7 | 与正文行距一致 |
| `minimap.enabled` | `false` | kernel 一般 50–300 行，minimap 是噪声 |
| `stickyScroll.enabled` | `true` | 长 kernel 里保住函数签名 |
| `bracketPairColorization` | `true`（用自己的四个色） | 模板嵌套深 |
| `renderWhitespace` | `selection` | 避免 Python DSL 的缩进错误 |
| `tabSize` | 4（CUDA）/ 4（Python DSL） | 对齐惯例 |
| `scrollBeyondLastLine` | `false` | |
| `padding` | 上 16 下 24 | 底部留白让最后一行不贴边 |

### 语法高亮主题

自定义两套 Monaco 主题，token 色直接取自全站调色板，避免"编辑器是一个嵌入的异物"：

| token | 亮色 | 暗色 |
| --- | --- | --- |
| 关键字 | `#7B5FB0` | `#A98FE0` |
| 类型 / 内置 | `#2C6E63` | `#62B5A4` |
| 函数名 | `#3A5C9A` | `#7FA8E8` |
| 字符串 | `#8A6A3B` | `#D6B27A` |
| 数字 | `#B4762A` | `#DDA24E` |
| 预处理 / 宏 | `#8A4A8F` | `#C090C6` |
| 注释 | `#5B6467` 斜体 | `#6C7376` 斜体 |
| 变量 | `#191C1F` | `#DFE3E2` |

四种语言都要注册：CUDA C++（用 `cpp` 的 Monarch 语法 + 自加 `__global__`、`__shared__`、`half`、`nv_bfloat16`、`cutlass::` 等关键字），TileLang / TIRx / CuTe DSL 用 Python 语法加各自的装饰器与常用符号。CuTe DSL 另需一个轻量规则把 `cute.*`、`cutlass.*` 标成类型色。

### 自动保存

- 输入停止 **800ms** 后写 `localStorage`，key `perfgame:draft:<slug>:<language>`。
- 值是信封：`{code, savedAt, problemVersion}`。保留最近 3 份，按时间倒序。
- 打开题目时：若本地草稿比服务端最近一次提交新，顶部显示一条可关的提示"有未提交的本地修改 · 恢复 / 丢弃"。
- 提交成功后清除该语言的草稿。
- 存储写入用 try/catch 包住：`localStorage` 满时降级为只保留最新一份，并提示。

### 校验、补全、格式化 —— 全部在浏览器内

这是硬要求：部署链路不稳定，这三件事不能依赖网络往返。

| 能力 | 实现 | 触发 |
| --- | --- | --- |
| 语法检查 | Monaco 内置词法诊断（括号、字符串、预处理行）；语义级检查不做 | 输入时 |
| 补全 | 静态词表 JSON（CUDA API、`cutlass::` 常用类型、四种 DSL 的装饰器与 primitives，约 800 条），前缀 + 子串匹配 | 输入 1 个字符后 |
| 格式化 | `clang-format` 的 WASM 版跑在 Web Worker（CUDA）；Python DSL 用 `ruff` WASM 或 `black` WASM | `Ctrl/Cmd+Shift+F` 或工具条按钮，**不在输入时自动跑** |

格式化只在显式操作时执行——自动格式化会在光标位置跳动时打断思路，而且 WASM 初始化有几百毫秒。

补全词表放在 `frontend/src/editor/dicts/*.json`，构建时打包，不请求接口。

### 编译产物

底部工具条三个标签：`PTX` / `SASS` / 编译日志。CUDA 语言不显示"源码"标签（源码就是用户正在编辑的东西）。CuTe DSL 无 CUDA 源码，同样只有 PTX / SASS。

点击标签在编辑区覆盖一个只读的 Monaco 实例（不是弹窗），带行号、可搜索、可全选复制。右侧固定"复制"与"下载"。

## 主题切换

- 三态：跟随系统 / 亮 / 暗。默认跟随系统。
- 存在 `localStorage` 的 `perfgame:theme`，未设置时用 `prefers-color-scheme`。
- 切换时给 `<html>` 加 `data-theme="dark"`，CSS 变量随之改变；同时 `monaco.editor.setTheme()`。
- **切换不做过渡动画**。颜色渐变会让代码闪一下，视觉上更脏。过渡时长设为 0。
- `<meta name="color-scheme">` 同步设置，避免滚动条与原生控件仍是另一套配色。

## 动效

只有三处：

1. **首次进入题目页**：题面与编辑器两个面板各自 `translateY(6px) → 0` + 淡入，编辑器延后 80ms。一次性，不重复。
2. **结果托盘**：从底部升起，200ms，`cubic-bezier(.2,.8,.2,1)`。
3. **折叠行展开**：高度过渡 160ms。

没有：卡片悬停上浮、按钮缩放、渐变加载骨架、滚动视差。

`prefers-reduced-motion: reduce` 时全部降为立即切换。

## 状态设计

| 状态 | 表现 |
| --- | --- |
| 排队中 | 结果区显示"队列中 · 前面 3 个任务"，`--signal` 细进度条（不确定态） |
| 等待 GPU | "等待空闲 GPU · 已等 42 秒"，附当前卡名与占用率 |
| 编译中 | 编辑器工具条上出现 `--primary` 的细不确定进度条 |
| 编译失败 | 结果区内联错误块，行号可点击跳转到编辑器对应行 |
| 测试点失败 | 折叠行左侧 `--danger` 竖条，展开显示期望与实际 |
| 全部通过 | 总分用 `--primary`，rail 上的方块全绿 |
| 空状态（无提交） | "还没有提交过。写完上面的 kernel，按提交。" |
| 断网 | 顶部一条常驻窄条"离线 · 编辑器可用，提交需要网络"，不弹窗 |

错误文案不道歉、不含糊。写"编译失败：第 14 行 `__shared__` 数组超过 48 KB 上限"，不写"出了点问题"。

## 无障碍

- 焦点环：2px `--primary`，`outline-offset: 2px`，绝不 `outline: none`。
- 所有交互元素可 Tab 到达；拖拽分隔条支持键盘（方向键 ±2%）。
- 颜色不是唯一信息载体：rail 上通过 / 未通过除颜色外用实心 / 空心方块区分；状态点旁始终有文字。
- 正文与背景对比度 ≥ 4.5:1，大字 ≥ 3:1。`--signal` 在亮色底上只用于大字或图元。
- 编辑器内 `aria-label` 描述语言与文件名。
- 页面 `lang="zh-CN"`；代码块 `lang` 属性正确标注。
